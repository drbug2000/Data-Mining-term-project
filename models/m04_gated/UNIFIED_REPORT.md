## 0. 용어 정의

F1 점수는 "상위 몇 개를 클릭으로 예측할지(임계값)"에 따라 달라진다. 임계값을 **어떻게
정하느냐**로 두 종류의 F1 을 구분한다.

| 본 보고서 용어 | 의미 | 제출 가능? |
|---|---|---|
| **실측 F1** (honest) | 임계값을 **학습 데이터만으로** 정하고 외부 검증셋에 적용해 잰 F1. 실제 제출 시 받을 점수. | ✅ |
| **상한 F1** (oracle) | 외부 검증셋의 **정답을 미리 보고** 최적 임계값을 고른 F1. 이론적 상한, 비교용. | ❌ (커닝) |

- **실측 F1** 의 임계값 정하는 방식 두 가지를 병기한다:
  - *사전확률 임계값*: 학습셋 클릭률(≈1.11%) 만큼 상위를 클릭 예측 (외부 정답 0개 사용).
  - *교차검증(OOF) 임계값*: 내부 검증을 5-겹으로 나눠 추정한 최적 비율의 평균.
- 핵심 원칙: 외부 검증셋 정답(`click_validation_answer`)을 **임계값·하이퍼파라미터 선택에
  쓰면 커닝(상한 F1)** 이다. 본 연구의 모든 선택은 학습 데이터 내부에서만 이뤄진다.

## 2. 검증 분할: Sorted vs Random — **Sorted SearchID 분할 채택**

> **질문**: 학습 데이터를 내부 학습/검증으로 나눌 때 SearchID 를 정렬해서(앞 80%/뒤 20%)
> 나눠야 하나, 무작위로 나눠야 하나?

**결론: Sorted SearchID 분할.** 단, 둘 다 **SearchID 단위(group) 분할**이라는 전제 위에서다.

### 2.1 먼저 — 두 방식 공통: SearchID 단위로 나눠야 한다 (leak 방지)
한 검색(SearchID)에는 광고가 여러 개 노출된다. 행(row) 단위로 무작위 분할하면 **같은
검색의 광고들이 학습/검증 양쪽에 쪼개져** 세션 통계가 새어든다(leakage). 그래서 Sorted든
Random이든 **SearchID 통째로 한쪽에만** 배정한다. 이건 둘 다 지킨다.

### 2.2 Sorted 를 택하는 이유
1. **순서 정보 보존**: 데이터셋 명세상 검색 스트림은 시간순(80/10/10)으로 구성된다.
   SearchID 가 시간 순서의 대리(proxy)이므로, 앞 80% 학습 → 뒤 20% 검증은 "과거로 학습,
   미래로 검증" = **실제 배포 상황과 일치**한다. 무작위 분할은 미래 검색을 섞어 학습/선택에
   쓰게 되어 낙관적 편향 위험이 있다.
2. **내부→외부 일반화 격차가 더 작다 (실측)**: KoSKNCP 가 5-seed 로 측정한 결과,
   내부검증 F1 과 외부검증 F1 의 격차가 **Sorted 0.0134 < Random 0.0159**. 격차가 작다는 건
   내부에서 고른 파라미터가 외부에 더 잘 전이된다는 뜻 → Sorted 채택.
3. **결정성/재현성**: Sorted 는 시드 없이 항상 같은 분할 → 재현 쉬움.

### 2.3 단서 (정직하게)
- **효과는 작다**: 두 방식의 외부 F1 차이(0.0924 vs 0.0914)는 §3.2 부트스트랩 신뢰구간
  (폭 0.07) 안의 노이즈다. "둘 다 leak-free 이고, Sorted 가 약간 더 안전한 기본값" 이 정확한
  표현이다.
- **데이터 확인**: 외부 검증의 SearchID 가 학습과 **같은 번호 범위에 섞여(interleaved)** 있고
  (학습 최댓값보다 큰 외부 ID = 0%), 정렬 구간별 클릭률/HistCTR 에 추세가 없다. 즉 SearchID 가
  완벽한 시간축은 아니다. 그래도 Sorted 의 "순서 보존 + 더 작은 격차" 근거는 유효하다.
- **더 본질적 한계**: Sorted/Random 모두 내부검증의 **미관측 유저 비율이 ≈1.3%** 인데
  외부검증은 **29%** 다. 즉 내부검증이 외부보다 "따뜻하다(warm)". 외부의 cold-start 를 더
  정직하게 흉내내려면 **유저 단위 holdout** 이 필요하다(향후 과제). 이건 Sorted/Random 선택과
  별개의 축이다.

## 3. 통합 모델과 엄밀 검증

### 3.1 통합 모델
로그-오즈 선형(나이브 베이즈)에 **양쪽의 모든 신호**를 결합, F1 목적함수로 좌표상승
(w_min=0.5, KoSKNCP 정규화)으로 가중치 학습:

```
lo = w1·log HistCTR + w2·log ad_ctr + w3·log ip_ctr + w4·log dev_ctr + w5·log cat_ctr
   + log(1.7)·[비로그인]                              # 고정 offset
   + w6·위치보정(IPS) + w7·검색내 순위                # KoSKNCP
   + w8·z(content 앙상블)                             # m04: 클릭 학습 head (강신호)
   + w9·SKNCP + w10·이웃광고 CTR                       # KoSKNCP: 협업필터, 이웃 CTR
score = σ(lo)
```
모든 선택은 학습 내부 80/20 분할에서만. CTR/SKNCP 인덱스는 내부검증→내부학습,
외부검증→전체학습. 임계값=교차검증/사전확률(외부정답 0개). 외부정답은 최종 채점만.

### 3.2 신호 조합 비교 (외부 검증)

| 신호 조합 | 실측 F1 (OOF 임계) | 실측 F1 (사전확률) | 상한 F1 | **외부 AUC** |
|---|---:|---:|---:|---:|
| 최소 (5CTR+content) | 0.0857 | 0.0885 | 0.0965 | 0.7081 |
| +위치+순위 | 0.0874 | 0.0841 | 0.0949 | 0.7089 |
| +SKNCP+이웃 | 0.0943 | 0.0885 | 0.0988 | 0.7095 |
| **전체 10신호 (합집합)** | **0.0958** | 0.0885 | 0.1018 | 0.7100 |
| KoSKNCP식 (content 없음) | 0.0931 | 0.0664 | 0.1007 | 0.7029 |
| **m04 단독¹ (자유적합, 5CTR+content)** | 0.0983 | **0.1062** | 0.1106 | **0.7133** |

¹ `exp_content_strong.py` (w_min 없는 자유 F1-적합 + 사전확률 임계값). 통합 하베스의
w_min=0.5 정규화는 이 경우 약간 손해 — 자유 적합이 더 나음(역시 노이즈 범위 내).

### 3.3 부트스트랩 신뢰구간 (2000회 재표집, 외부 실측 F1)
```
평균 = 0.0843   표준편차 = 0.0177   95% 신뢰구간 = [0.0518, 0.1214]  (폭 0.070)
```
**→ 결정적 발견**: 신뢰구간 폭이 0.07 (양성 229개). 따라서 **m04(0.106)·KoSKNCP(0.094)·
합집합(0.096)의 차이는 전부 통계적 노이즈**(최소 유의차 ≈ 0.039 > 관측 격차). 어떤 단일
조합도 통계적으로 우월하지 않다. **유일하게 안정적인 비교 지표는 AUC** (0.70~0.713).

### 3.4 신호 제거실험 (leave-one-out)
추가 신호(SKNCP/위치/순위/이웃/ip/dev)를 하나씩 빼도 실측 F1 변화가 ±0.01~0.02 (전부
신뢰구간 내) — **어떤 추가 신호도 통계적으로 유의하게 기여하지 않음**. 두 원 보고서가 각각
관찰한 "추가 신호가 성능을 깎음 / 정보 천장" 을 **세 번째 독립 구성(합집합)으로 재확인**.

### 3.5 유저 이력 층화 검증 (cold / search-only / warm)

권장 모델(5CTR + content 앙상블, 사전확률 임계값)을 외부 검증의 각 유저가 **학습 데이터에서
가졌던 이력**으로 3층으로 나눠 분석. 층 정의는 학습 내부-train 만으로(leak-free):
- **cold**: 학습에서 처음 보는 유저, **search-only**: 검색은 있으나 클릭 0회, **warm**: 클릭 ≥1회.

| 층 | 행수 | 비중 | 클릭률 | AUC | precision | recall | **F1** |
|---|---:|---:|---:|---:|---:|---:|---:|
| cold | 5,871 | 29.4% | 1.38% | 0.682 | 13.3% | 9.9% | **0.1135** |
| search-only | 9,861 | 49.3% | 0.97% | 0.729 | 15.2% | 5.2% | 0.0775 |
| warm | 4,268 | 21.3% | 1.22% | 0.717 | 8.5% | 21.2% | **0.1209** |
| **전체** | 20,000 | 100% | 1.15% | 0.713 | 10.8% | 10.5% | **0.1062** |
(전역 사전확률 임계값으로 상위 예측한 뒤 층별로 분해 — 층별 F1 이 전체로 합성됨)

**읽기**:
- **warm 이 엔진**(F1 0.1209, recall 21%): entity CTR + content 신호가 모두 살아있는 층.
- **cold 도 content 가 다리(bridge) 역할**(F1 0.1135): AUC 는 0.682 로 가장 낮지만(처음 보는
  유저라 entity 신호 없음), 클릭 학습 content head 가 메워 F1 을 warm 수준 가까이 유지.
  → content 앙상블 채택의 직접 근거(외부 cold-start 29% 를 살림).
- **search-only 가 F1 사각지대**(0.0775, 49% 데이터): AUC 는 0.729 로 가장 높은데 F1 은 최저 —
  랭킹은 되지만 양성을 임계값 위로 못 밀어올림(AUC↛F1 지문). 남은 천장이 여기 국지화.

## 4. 결론

1. **두 방법론은 통계적으로 동등**하다. 외부 실측 F1 ≈ 0.09~0.11 은 부트스트랩 신뢰구간
   (폭 0.07) 안의 단일 분포 — m04 / KoSKNCP / 합집합 모두 구별 불가.
2. **유일한 안정적 우위(AUC 기준) = 클릭으로 학습한 content head 앙상블**(m04). 외부 AUC
   0.7133 으로 양쪽 원본(0.671/0.710)을 상회. 비학습 SKNCP(0.593)보다 학습 head(0.684)가 우월.
3. **신호를 더 합쳐도(합집합) 이득 없음** — 용량·피처 추가 모두 노이즈 또는 성능 저하.
   GBDT(비선형 용량↑)는 외부 0.078 로 과적합. → **천장은 정보량이지 모델 용량이 아님**
   (세 독립 구성 + GBDT 반증으로 확고).
4. **상한 F1(0.11)** 은 외부정답으로 임계값을 고른 수치이며, 실측 천장(~0.10)과 통계적으로
   구별 불가. **제출 가능한 최선 = 실측 F1 ≈ 0.106** (5CTR + 강한 content, 사전확률 임계값).

**권장 최종 모델**: `exp_content_strong.py` (5-CTR + 10-seed content 앙상블, 자유 F1-적합,
사전확률 임계값) — 실측 F1 0.1062 / AUC 0.7133. KoSKNCP 에서 채택할 것: **w_min 정규화 개념
+ 부트스트랩 신뢰구간 검증 + 교차검증 임계값**(통계적 정직성). 추가 신호(SKNCP/위치/순위)는
노이즈라 미채택.
