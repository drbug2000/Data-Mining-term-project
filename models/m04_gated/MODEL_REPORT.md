# 권장 모델 설명서 — 5-CTR + Content 앙상블 (직관 중심)

실측 F1 **0.1062**, 외부 AUC **0.7133** (leak-free). 코드: `experiments/exp_content_strong.py`.
이 문서는 "이 모델이 무엇을, 왜, 어떻게" 를 수식 최소화로 설명한다.

---

## 1. 한 줄 요약

> "**여러 과거 클릭률 신호 + 검색어-광고 의미 매칭**을, 각자 신뢰도만큼 곱해서 점수를 내고,
> 점수 높은 상위 ~1.1% 를 '클릭'으로 예측한다."

광고 클릭은 1.1% 밖에 안 되는 **희귀 사건**이라, 정답을 맞히는 게 아니라 **"클릭할 것 같은
소수를 랭킹 최상단에 모으는"** 문제다. 그래서 여러 약한 신호를 잘 합치는 게 핵심.

---

## 1.5 왜 이 설계인가 — EDA 로 전제 검증

모든 설계 선택은 **데이터 분석(EDA)에서 측정한 사실**에서 도출됐다. (수치는 이 데이터셋에서
직접 측정; 재현: `/tmp/eda.py` 형식)

| # | 설계 전제 | **EDA 측정 근거** | 방법 반영 |
|---|---|---|---|
| 1 | 극단 불균형 → "정답 맞히기"가 아닌 **랭킹 최상단 문제** | 클릭률 **1.11%** (외부 229/20,000) | **F1 직접 최대화**(좌표상승). log-loss 최적은 비클릭에 끌려 F1 0.046 |
| 2 | 검증셋은 **처음 보는 세션** → 세션 통계는 무효, 일반화 신호 필요 | train↔외부 SearchID 겹침 **0.01%**, **미관측 유저 29%** | 세션 무관 신호(엔티티 CTR) + **content head(텍스트만으로 100% 커버)** |
| 3 | **직접 텍스트 유사도는 거의 무의미** → 학습 필요 | 검색어-광고 raw cosine **단독 AUC 0.530** (Cohen's d 0.10) | 그냥 cosine 대신 **클릭으로 학습한 content head**(학습 후 AUC 0.684) |
| 4 | HistCTR 이 강하지만 **희소 광고엔 불안정** | HistCTR 구간별 CTR **0.6%→1.2%→2.3%→5.1%→7.6%** 단조↑ (단독 AUC 0.670) | log(HistCTR)을 **사전 log-odds 시작점**으로, 약한 CTR은 **Laplace 평활** |
| 5 | **위치 편향** 존재 | Position 1 **1.29%** vs Position 7 **0.71%** (1.8배) | HistCTR 이 (광고,위치)로 키잉돼 위치효과 내포 → m04 는 별도 위치항 없이 흡수 (KoSKNCP 는 IPS 항으로 명시 보정) |
| 6 | 로그인 여부가 약한 신호 | 비로그인 **1.20%** vs 로그인 **0.99%** (비율 1.21) | 비로그인 행에 **고정 offset**(현재 log(1.7); EDA상 ~log(1.2)면 충분 — 저가중 보조항) |
| 7 | 검색당 광고가 거의 1~2개 | 1개 **57%**, 2개 **43%** (최대 2) | "검색 내 상대순위" 신호는 효과 제한적(절반이 광고 1개) → m04 는 미채택, **Task1 은 검색별 랭킹이 아니라 전체 global F1** 임이 여기서 정당화됨 |

**핵심 결론**: 전제 2·3(cold-start + 텍스트 유사도 무의미)이 이 모델의 존재 이유다. 검증셋의
29% 가 처음 보는 유저라 CTR 신호가 죽는데, 그 자리를 **클릭으로 학습한 content head** 가
메운다(§6 층화에서 cold 층 F1 0.114 로 입증). 전제 1 은 학습 목적함수(F1 좌표상승)를 결정한다.

## 2. 점수 = 신호들의 "가중 곱" (= 로그선형)

확률을 곱하면 1을 넘을 수 있어 수학적으로 안 맞다. 그래서 **로그(log) 공간에서 더한다**
(나이브 베이즈: 독립 증거는 log-odds 에서 선형 결합).

```
점수(검색어 q, 광고 a) = σ(  w1·log(HistCTR)
                          + w2·log(ad_ctr)
                          + w3·log(ip_ctr)
                          + w4·log(dev_ctr)
                          + w5·log(cat_ctr)
                          + (로그인 안 했으면 +0.53)        ← 고정
                          + w6·z(content 점수)  )
```
- 직관: 각 신호가 "이 광고 클릭될 확률"에 대한 **증거 한 표**씩 던지고, 가중치 wᵢ 만큼
  크게 반영. σ(sigmoid)는 합산 증거를 0~1 확률로 변환.
- log 를 쓰는 이유: CTR 0.5%↔5% 같은 배수 차이를 균형 있게(곱셈→덧셈) 다루기 위함.

## 3. 신호 7가지 — 무엇이고 어디서 오나

### 3.1 신뢰 클릭률(CTR) 5개 — "과거에 얼마나 클릭됐나"
모두 학습 데이터의 클릭 빈도. **Laplace 평활**로 관측 적은 경우를 전역평균(≈1.11%)으로 당김
`(클릭+20·전역)/(노출+20)`. 처음 보는 키는 전역평균으로 대체.

| 신호 | 무엇의 클릭률 | 직관 |
|---|---|---|
| **HistCTR** | 그 (광고,위치) 조합 | 검색엔진이 직접 준 과거 추정 — **단일 최강 신호** |
| **ad_ctr** | 그 광고(AdID) | 이 광고 자체가 인기인가 |
| **ip_ctr** | 그 IP(IPID) | 이 접속 IP가 잘 클릭하나 |
| **dev_ctr** | 그 기기(UserDeviceID) | 이 기기/유저가 잘 클릭하나 |
| **cat_ctr** | 그 카테고리 | 이 광고 카테고리가 잘 클릭되나 |

### 3.2 Content 점수 (content head) — "검색어와 광고가 의미상 맞나"
- 검색어 임베딩(384차원) + 광고제목 임베딩(384차원)을 각각 작은 신경망(MLP 384→256→128)으로
  투영 → 코사인 유사도 → `scale·cos+bias`.
- **클릭으로 학습** (클릭=1 가깝게, 비클릭=0). seed 10개 평균(앙상블)로 안정화.
- 그냥 두 임베딩 코사인(비학습)은 거의 무의미(AUC 0.518)지만, **학습하면 AUC 0.684**.
- AdID/유저 없이 **텍스트만으로 점수** → 처음 보는 유저/광고(cold-start)에서 유일하게 작동하는
  100% 커버리지 신호. (외부 검증의 29% 미관측 유저를 살리는 핵심 — §6 층화 참고)

### 3.3 로그인 offset (고정)
EDA: 비로그인 클릭률(1.34%) > 로그인(0.83%), 비율 1.61. 로그인 안 한 행에 `log(1.7)≈0.53`
고정 가산(가중치 학습 안 함).

## 4. 가중치(weight)는 어떻게 나왔나 — 핵심 질문

### 4.1 무엇을 최적화하나
가중치 wᵢ 를 **F1 점수를 직접 최대화**하도록 정한다. (보통 쓰는 로그손실(log-loss)은 다수
클래스인 '비클릭'에 끌려가 F1과 어긋남 — log-loss 최적 모델 F1 ≈ 0.046 vs F1 직접최적 ≈ 0.10.)

### 4.2 어떻게 — 좌표상승(Coordinate Ascent), 욕심쟁이 방식
> "한 번에 가중치 **하나만** 움직여서, F1 이 가장 좋아지는 값으로 고정. 신호들을 한 바퀴 돌고,
> 더 안 좋아질 때까지 반복."

```
w = [1,1,1,1,1,1] 로 시작
반복(최대 ~10회):
  각 신호 j 에 대해:
    w[j] 를 {0, 0.5, 1.0, ..., 3.0} 후보로 하나씩 바꿔보고
    내부검증 F1(상위 top-k) 이 최고가 되는 값으로 w[j] 고정
  한 바퀴 돌아 개선 없으면 종료
```
- F1 은 미분 불가(랭킹 기반)라 경사하강 대신 **격자 탐색 + 좌표별 최적화**.
- 후보에 **0 포함(자유적합)** → 쓸모없는 신호는 가중치 0으로 **자동 제거** 가능.

### 4.3 실제 학습된 가중치 (seed=42, sorted 80/20 내부분할)

| 신호 | 학습 가중치 | 해석 |
|---|---:|---|
| **HistCTR** | **2.5** | 가장 강한 신호 → 높게 |
| ad_ctr | 0.5 | 낮음 — HistCTR/dev 와 정보 중복 |
| **ip_ctr** | **2.0** | IP별 클릭 성향 유효 |
| **dev_ctr** | **2.5** | 기기별 성향 강하게 반영 |
| cat_ctr | **0.0** | **제거됨** — ad/ip/dev 가 있으면 카테고리 CTR 은 잉여 |
| **content** | **2.0** | 의미 매칭 강하게 반영 (cold-start 핵심) |
| 로그인 offset | 0.53 (고정) | EDA 기반, 학습 안 함 |

**읽기**: 좌표상승이 스스로 (1) HistCTR·dev_ctr 를 가장 신뢰, (2) content 를 강하게 채택,
(3) **cat_ctr 은 잉여라 0으로 버림** — 사람이 고른 게 아니라 F1 최대화 과정에서 자동 결정.
내부검증 F1 = 0.1124.

> 주의: 이 가중치는 내부검증 분할/시드에 따라 ±조금 흔들린다. 부트스트랩상 F1 0.01 차이는
> 노이즈라(§UNIFIED §3.3), 가중치의 절대값보다 "강신호=HistCTR/dev/content, 잉여=cat" 라는
> **패턴**이 본질.

### 4.4 방법론 명세 (재현 정확값)

**(A) Content head 학습** — `exp_content_strong.py`
```
입력  : 검색어 임베딩 q(384), 광고제목 임베딩 a(384)  (MiniLM-L12-v2, 사전학습, 동결)
구조  : 양쪽 MLP  Linear(384→256)+ReLU+Linear(256→128) → L2정규화 → cos → scale·cos + bias
손실  : BCEWithLogits, pos_weight = (비클릭수/클릭수) ≈ 89   (희귀 양성 보정)
최적화: Adam, lr 1e-3, weight_decay 1e-3, 배치 8192, 최대 55 epoch
조기종료: 내부검증(iva) AUC, patience 8
앙상블: seed 1~10 의 logit 평균 (분산 감소; 단일 0.677 → 앙상블 0.684 AUC)
정규화: content logit 을 내부학습(itr) 행의 평균/표준편차로 z-score
```

**(B) 신뢰 CTR (5개)** — Laplace 평활
```
ĈTR(e) = (클릭수(e) + 20·전역CTR) / (노출수(e) + 20),   미관측 e → 전역CTR(≈0.0111)
키 e ∈ {(광고,위치)=HistCTR(데이터제공), AdID, IPID, UserDeviceID, CategoryID}
내부검증 행의 CTR = 내부학습 카운트로만(자기 클릭 누수 방지) / 외부 행 = 전체학습 카운트
```

**(C) 가중치 학습** — F1 좌표상승(coordinate ascent)
```
점수 sᵢ = Σⱼ wⱼ·featⱼ(i) + log(1.7)·[비로그인]
목적   = 내부검증 F1 (점수 내림차순 상위 k 를 1, k 는 F1 최대화 지점)
탐색   = w=[1..1] 초기 → 각 wⱼ 를 {0,0.5,1.0,...,3.0} 격자로 훑어 F1 최고값 고정
         → 신호 한 바퀴 순회, 개선 없을 때까지(최대 10 pass). 0 허용=잉여신호 자동 제거(자유적합)
```

**(D) 임계값(예측 비율)**: 학습셋 클릭률(≈1.11%) — §5. (대안: 내부검증 5-겹 OOF 비율 평균)

**(E) 분할**: 학습데이터 SearchID 정렬 후 앞 80% 내부학습(itr) / 뒤 20% 내부검증(iva).
근거 `UNIFIED_REPORT §2`.

## 5. 임계값(threshold) — 몇 개를 '클릭'이라 할까

점수만으론 0/1 예측이 안 되니 **상위 몇 %를 클릭으로 찍을지** 정해야 한다.
- 외부 정답을 보고 최적 비율을 고르면 **커닝(상한 F1)**.
- 본 모델은 **학습셋 클릭률(≈1.11%)** 을 그대로 비율로 사용 → 외부 정답 0개 (정직).
  20,000개 중 상위 ≈223개를 클릭으로 예측.

## 6. 성능

### 6.1 전체 (외부 검증 20,000행)
| 지표 | 값 |
|---|---|
| **실측 F1** (사전확률 임계값) | **0.1062** |
| 외부 AUC | **0.7133** |
| content 단독 AUC | 0.684 |
| (참고) 상한 F1 | 0.1106 |

부트스트랩 95% 신뢰구간 [0.052, 0.121] — 양성 229개라 노이즈 큼. 0.1062 는 "현 신호로
달성 가능한 실측 천장" 부근.

### 6.2 유저 이력 층화 (cold / search-only / warm)
유저가 학습에서 가졌던 이력으로 3층 분해 (정의는 내부-train 만 = leak-free):

| 층 | 비중 | AUC | F1 | 한 줄 |
|---|---:|---:|---:|---|
| **warm** (클릭 이력 有) | 21% | 0.717 | **0.121** | 엔진 — CTR+content 둘 다 살아있음 |
| **cold** (처음 보는 유저) | 29% | 0.682 | **0.114** | content 가 다리 — CTR 없어도 의미매칭이 메움 |
| search-only (검색만, 클릭X) | 49% | 0.729 | 0.078 | 사각지대 — 랭킹은 되나(AUC↑) 최상단에 못 밀어올림 |

→ **content head 채택의 직접 근거**: 외부 29% cold 유저에서 CTR 신호가 죽어도 content 가
F1 0.114 로 warm(0.121)에 근접하게 유지. content 없으면 이 층이 무너진다.

## 7. 정직성(leak-free) 보장

| 결정 항목 | 어디서 정했나 |
|---|---|
| content head 학습/조기종료 | 학습 내부 80/20 분할의 내부검증 AUC |
| 가중치 wᵢ (좌표상승) | 내부검증 F1 |
| 임계값 비율 | 학습셋 클릭률(외부 정답 0개) |
| CTR 통계 | 내부검증용=내부학습 카운트 / 외부용=전체학습 카운트 (자기 클릭 누수 방지) |
| **외부 정답 (`click_validation_answer`)** | **최종 F1/AUC 보고에만** — 선택·학습에 일절 미사용 |

분할은 **Sorted SearchID 80/20**(시간순 보존 + 내부↔외부 격차 더 작음). 자세한 근거는
`UNIFIED_REPORT.md §2`.

## 9. 핵심 메시지

1. 모델은 **5개 CTR + 클릭학습 content 매칭**을 F1 직접최적 가중치로 곱한 단순·해석가능한 점수기.
2. 가중치는 **좌표상승이 F1 최대화로 자동 결정** — HistCTR/dev/content 강신호, cat_ctr 잉여(0).
3. **content head 가 cold-start(미관측 29%)를 살리는 핵심 차별점** (층화로 입증).
4. 실측 F1 0.1062 는 leak-free 천장 부근 — 더 올리려면 모델 용량이 아니라 **새 정보**가 필요.
